# 实现阶段设计细化

需求基线：需求v1.1、设计v1.1；FR14仍延期。以下记录实际实现与设计之间的技术差异，不能静默视为原设计已经逐字落地。

| 编号 | 决定与原因 | 影响与验证 |
|---|---|---|
| IMPL01 | 写事务目前统一包含全部7个object store，以简化恢复/隔离和普通写入之间的互斥；同源全部写仍由meta版本校验 | 不改变原子性/业务语义，锁粒度较设计粗；NFR02需实测后再决定细化 |
| IMPL02 | byQuestion索引使用[profileId,questionKey]读取该键事件，再按submittedAt/practiceId/ordinal排序，保持与导入重放相同顺序 | DAT-02/04，DT05；减少索引键字段，但高重复题目历史需性能测试 |
| IMPL03 | 元数据损坏时创建仅限Worker会话内的恢复令牌，提供只读故障页，只允许已校验备份替换或双重确认清空；该令牌不代表已有数据已保存 | FR08/FR10、DT12；库中旧数据在确认之前保持不变，恢复后生成新epoch |
| IMPL04 | 发布托管仅接收编译后的HTML/JS/CSS及站点manifest；源码、设计和需求文件由Gitee管理，不向Sites源仓库同步完整工作目录 | FR12、NFR05；静态部署不接触学习数据 |
| IMPL05 | 首版采用内存页面导航，刷新返回首页，再从草稿入口继续；不承诺深链接定位到具体题单 | 与设计hash路由实现不同，但保留FR08草稿恢复；无需求条目要求深链接；浏览器刷新回归已覆盖 |

显示“已保存”的唯一依据仍是IndexedDB事务complete；公共站点与Gitee仓库不是云数据备份。
